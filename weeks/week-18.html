本週自學導讀

期末整合時，先把所有額外成本換成 cycles per instruction，再與 base CPI 相加；最後乘 instruction count 與 cycle time。這能把 branch、data hazard 與 cache miss 放進同一個可驗證模型。

概念推導

建立整合 CPI

CPI_total = CPI_base + data-stall CPI + control-stall CPI + memory-stall CPI。每一項都應由事件頻率乘每次事件 penalty 得到，例如 branch frequency × misprediction rate × penalty。

若 instruction 與 data cache 都可能 miss，需分別依 instruction fetch frequency 與 load/store frequency 計算。所有指令都有一次 instruction fetch，但只有部分指令存取 data cache。

答案的三層檢查

結構檢查：bit fields 是否加總正確、pipeline 是否維持程式相依、cache set 是否由 index 唯一決定。數學檢查：機率是否介於 0 與 1、時間單位是否一致。語意檢查：最終 register 與 memory 結果是否符合原程式。

自學完成的標準不是能認出圖，而是能從空白紙重建：畫出必要元件、標出資料方向、寫出控制條件，再用一個具體指令或位址走完整條路。

Worked example

整合 Branch 與 Cache Stall

10^9 instructions、2 GHz、base CPI=1；branch 15%、mispredict 8%、penalty 3；load/store 30%、L1 miss 4%、penalty 50。

  1. Branch stall CPI = 0.15×0.08×3 = 0.036。
  2. Memory stall CPI = 0.30×0.04×50 = 0.60。
  3. Total CPI = 1+0.036+0.60 = 1.636。
  4. CPU Time = 10^9×1.636/(2×10^9) = 0.818 秒。

結論：此例 memory stalls 遠大於 branch stalls，因此優先降低 cache miss 或 miss penalty 較有潛力。

常見誤解

  • 把 penalty 直接加到 CPI，沒有乘事件頻率。
  • 對所有指令套用 data-cache miss rate，漏掉 load/store frequency。
  • 算出時間後沒有回查最終架構狀態是否正確。

自我檢核

先在紙上作答，再展開核對。能說明理由，才算真正掌握。

1. 為何 instruction-cache miss 不需再乘 load/store frequency？

每條執行中的指令都需要 instruction fetch，因此其基準頻率是每 instruction 一次。

2. 本例應先改善 branch 還是 memory？

在其他成本相近時，memory stall CPI=0.60，遠大於 branch stall CPI=0.036，優先改善 memory 較可能得到較大整體收益。

講義筆記

期末題目通常要求跨章節整合。例如一段 loop 的效能可能同時牽涉指令數、branch、load-use hazard 與 cache miss。

請避免只寫結論。每一步推導、每個控制訊號、每個 cache 位址切割都要有理由，這比背答案更可靠。

完成本課程後，應能用精確但不神秘的語言說明：程式為什麼快或慢，CPU 為什麼需要 pipeline，記憶體階層為什麼不可或缺。

學習路徑

  1. 觀察問題：先辨認本週主題要解決的現象，例如程式變慢、指令相依、cache miss 或位元解讀錯誤。
  2. 建立模型：把問題抽象成本週核心術語，並畫出資料、控制或位址如何流動。
  3. 套用方法：使用公式、指令格式、pipeline 時序表或 cache 位址切割完成分析。
  4. 檢查結果：確認單位、暫存器內容、控制訊號、hit/miss 或 cycle 數是否一致。
  5. 連回效能：說明這個主題如何影響 CPU time、CPI、correctness 或 memory behavior。
練習任務：以 3 分鐘短講方式，請每組說明期末專題中一個最重要的計算機組織概念與證據。

例題與講解

期末整合題架構

1. Count instructions or dynamic instruction mix
2. Identify pipeline stalls and branch penalties
3. Estimate memory stalls using cache miss rate
4. Combine into CPI and CPU Time

完整效能分析通常不是單一公式，而是把不同來源的 cycle cost 加回 CPI。

課後檢核

  1. 給一個位址，你能切出 tag/index/offset 嗎？
  2. 給一段 MIPS，你能畫出 pipeline hazard 嗎？
  3. 你能用一句話說明 hardware/software interface 嗎？
