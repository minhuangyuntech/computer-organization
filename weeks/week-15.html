核心概念

  • Direct-mapped：每個 memory block 只能放到一個 cache line。硬體簡單、hit time 短，但不同 block 若映到同 line，會互相趕走。
  • Fully associative：任何 memory block 可放到任一 cache line。Conflict miss 最少，但需要同時比對很多 tags，硬體成本高。
  • Set-associative：折衷設計。Cache 分成多個 sets，每個 set 有多個 ways。Block 由 index 選 set，再在 set 內任一 way 放置。
  • Miss 類型：Compulsory miss 是第一次存取；capacity miss 是 cache 太小；conflict miss 是 mapping 限制使 blocks 互相衝突。

本週自學導讀

Mapping 題先由容量求 sets，再由 sets 求 index bits，由 block size 求 offset bits，剩下才是 tag。這個順序能避免把 ways、sets 與 lines 混在一起。

概念推導

Direct、Set-associative 與 Fully Associative

Direct-mapped 每個 memory block 只有一個候選 line；N-way set-associative 有 N 個候選；fully associative 可放在任何 line。候選越多，conflict miss 越少，但 tag comparators、hit mux 與 replacement metadata 越多。

Set-associative cache 先用 index 選出一個 set，再平行比較該 set 每一 way 的 tag。Ways 不是 index 的額外 bits；它們是同一 index 下的多個候選位置。

位址切割公式

Sets = Cache data size / (block size × associativity)。Offset bits = log2(block size bytes)，index bits = log2(sets)，tag bits = address bits - index - offset。

容量題通常指 data capacity，不含 tag、valid、dirty 與 replacement bits。若題目問實際硬體儲存量，必須再把 metadata 加回每一 line。

Worked example

切割位址 0x12345678

使用上圖 cache 組態，求 offset、set index 與 tag。

  1. Offset = address & 0x3F = 0x38 = 56。
  2. Set index = (address >> 6) & 0x3F = 25。
  3. Tag = address >> 12 = 0x12345。
  4. 檢查：20+6+6=32 bits。

結論：此 block 只能放入 set 25，但可放在該 set 的任一個 4 ways。

常見誤解

  • 用 cache lines 數直接當 sets 數，漏除 associativity。
  • 認為 way number 來自 address bits。
  • 把 cache data capacity 與含 metadata 的總儲存量混用。

自我檢核

先在紙上作答，再展開核對。能說明理由，才算真正掌握。

1. 同容量與 block size 下，4-way 相較 direct-mapped 的 index bits 如何變化？

Sets 減為四分之一，所以 index bits 少 2；相應地 tag bits 多 2。

2. 64-byte block 需要幾個 offset bits？

log2(64)=6 bits。

講義筆記

n-way set associative cache 的 sets = cache size / (block size × n)。Index bits = log2(sets)，offset bits = log2(block size)。

Associativity 提高通常可降低 conflict miss，但也可能增加 hit time 與能耗。真實設計常以實驗工作負載評估。

手算題請先寫出 cache size、block size、ways，再推 lines、sets、offset/index/tag，不要跳步。

學習路徑

  1. 觀察問題：先辨認本週主題要解決的現象，例如程式變慢、指令相依、cache miss 或位元解讀錯誤。
  2. 建立模型：把問題抽象成本週核心術語，並畫出資料、控制或位址如何流動。
  3. 套用方法：使用公式、指令格式、pipeline 時序表或 cache 位址切割完成分析。
  4. 檢查結果：確認單位、暫存器內容、控制訊號、hit/miss 或 cycle 數是否一致。
  5. 連回效能：說明這個主題如何影響 CPU time、CPI、correctness 或 memory behavior。
練習任務：使用同一串位址，比較 direct-mapped、2-way、fully associative 的 hit/miss 結果，觀察 conflict miss 如何改變。

例題與講解

4-way set associative

Cache = 16KB, block = 32B, 4-way, address = 32 bits
Blocks/lines = 16KB / 32B = 512
Sets = 512 / 4 = 128 => index = 7 bits
offset = 5 bits
tag = 32 - 7 - 5 = 20 bits

每個 index 對應一個 set，set 內 4 個 ways 都要進行 tag 比對。
