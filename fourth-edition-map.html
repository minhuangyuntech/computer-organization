Chapter 4 concept bridge

MARIE 與 MIPS：相同狀態問題，不同 ISA 表達

MARIE 是第 4 版用來呈現基本計算機組織的累加器架構。它不是 MIPS 的縮小版，而是一個刻意簡化的模型：運算主要透過 AC，讓 register transfer 與指令週期容易逐步追蹤。

主要暫存器

Register寬度角色
AC16 bits累加器，保存算術與邏輯運算的主要 operand/result
MAR12 bitsMemory Address Register，指出要存取的 word
MBR16 bitsMemory Buffer Register，暫存從 memory 讀出或準備寫入的 word
PC12 bitsProgram Counter，指出下一個 instruction word
IR16 bitsInstruction Register，保存目前正在 decode/execute 的指令
InREG / OutREG8 bits輸入與輸出資料暫存器

Fetch 狀態轉移

  1. MAR ← PC
  2. MBR ← M[MAR]
  3. IR ← MBR
  4. PC ← PC + 1
  5. Decode IR[15:12]，並視指令使用 IR[11:0]

前四步完成取指與 PC 更新；最後一步才根據 opcode 決定 execute phase 需要哪些資料路徑。

面向MARIEMIPS

Worked example

計算 Z = X + Y。比較 MARIE 與 MIPS 需要顯式表示的狀態。

MARIE

Load X
Add Y
Store Z

MIPS

lw $t0, 0($s0)   # X
lw $t1, 4($s0)   # Y
add $t2, $t0, $t1
sw $t2, 8($s0)   # Z

MARIE 把第一個 operand 與 result 隱含在 AC；MIPS 把來源與目的暫存器寫在指令中。兩者都需要 memory read、ALU add 與 memory write，但 ISA 顯露的狀態不同。

MARIE 自我檢核

先寫出 register transfer 或位址單位，再展開答案。

1. 為何 MARIE 的 PC 加 1，而 MIPS 的 PC 通常加 4？

MARIE 以 16-bit word 為指令位址單位；MIPS memory 為 byte-addressed，固定指令長 4 bytes。

2. MAR 與 MBR 的角色有何不同？

MAR 指定位址；MBR 保存該位址讀出或準備寫入的資料。

3. MARIE 的 Add 為何不需要三個 register 欄位？

其中一個來源與目的都隱含為 AC，另一個 operand 由 address 欄位指定。
